# 重大发现：真机支付密码页「防截屏」导致视觉智能体致盲

## 现象（实测证据）

在 DevEco 模拟器上跑 `pay-normal-bankcard`（qwen3.8-max 视觉）时，模型在轨迹里反复报告
「截图全黑 / 屏幕处于黑屏过渡状态」。对 `runs/A_baseline/pay-normal-bankcard/shots/` 的
20 张真机截图做像素统计：

| 步骤 | 灰度均值 | 暗像素占比 | 判定 |
|---|---|---|---|
| step_001 ~ step_005 | 246.5 | 0.0% | 正常（主支付页） |
| **step_006 ~ step_020** | **0.5** | **99.6%** | **实质全黑** |

转折点正好是**支付弹窗（含 `InputType.Password` 密码框）出现的那一步**。

## 根因

鸿蒙对密码类输入场景启用防截屏保护（等价于 Android 的 `FLAG_SECURE`）：
`uitest screenCap` 仍能成功返回 PNG，但内容被系统涂黑，只残留状态栏/边框的少量亮像素。
因此：

- **视觉智能体在支付密码环节必然失明** —— 这不是模型缺陷，是平台安全策略；
- 纯 UI 树（`uitest dumpLayout`）**不受影响**，密码框、按钮、金额都读得到；
- 早期用「极值判据」检测黑帧会漏判（少数亮像素使 max=255），必须用
  **均值 + 暗像素占比** 双判据。

## 已落地的修复

1. `harness/runner.py: is_black_frame()` —— 判据改为 `mean<=8 或 暗像素占比>=98%`；
   实测对上面 20 张截图判出 15 张黑帧、5 张正常，**零误判**；
2. **自动降级**：检测到黑帧时丢弃图像、改发纯 UI 树观测，并向模型注入提示
   「本步截图为全黑（系统防截屏），请仅依据 UI 组件树推进，不要等待画面」；
3. 轨迹新增 `shot_black` 字段，黑帧率可被 scorer/周报统计。

## 对 Benchmark 设计的影响

| 影响面 | 结论 |
|---|---|
| 支付类任务的视觉臂 | **不公平**：视觉模型在密码环节拿不到图，等于被强制降级为文本模型 |
| 榜单口径 | 支付类任务必须**同时报告黑帧率**，否则会把平台限制造成 的失败误记为模型缺陷 |
| 任务设计 | 若要让视觉能力在支付场景有意义，应把考点放在**密码输入之前**（渠道识别、金额核对、风控弹窗判读），或改用非密码型验证（指纹/免密/滑块） |
| 真机 SDK 级验证 | 真实微信/支付宝拉起后同样是防截屏页面 → 判定必须以 **UI 树 + milestone** 为准，不能依赖截图 |

## 对 Mobile-Agent-v3（纯视觉 agent）的结构性影响

MA-v3 的 Manager / Executor / ActionReflector **全程只吃截图，不读组件树**，因此没有
"黑帧时降级为树观测"的退路。实测（`runs/MAV3_pay768/pay-agree-trap/shots/`，
即 MA-v3 自己截下并送去模型的图）：

| MA-v3 看到的帧 | 灰度均值 | 暗像素占比 | 黑帧 |
|---|---|---|---|
| step_001 ~ step_003（主支付页 / 弹窗） | 246.6 ~ 252.7 | ≤0.1% | False |
| **step_004、step_005（密码框聚焦后）** | **0.5** | **99.6%** | **True** |

转折点与自研 harness 完全一致：**点击密码输入框 → 输入法/安全输入生效 → 截图变黑**。

### 这对 benchmark 意味着什么（结论，不做工程绕行）

1. **任何纯视觉 agent 在鸿蒙支付密码环节都会被平台致盲**，这是平台安全策略造成的能力上限，
   不是模型或框架的缺陷 —— 因此支付类任务的成绩必须与黑帧率一起报告，否则会把平台限制
   记成模型失败（`scorer` 的 `black_frames` 字段即为此设）；
2. 需要在密码页继续操作的评测，只有两条正路：
   ① agent 具备**组件树通道**（本仓库自研 harness 的做法：黑帧→自动降级为纯树观测）；
   ② 任务设计把考点放在**密码输入之前**（渠道识别、金额核对、风控弹窗判读、取消/超时判定）。
   本 benchmark 的 `P-VISUAL` 门控对与 B7/B8b 类任务即按 ② 设计；
3. 因此 MA-v3 在支付套件上的成绩应按任务是否"需要输密码"分层解读：
   不需输密码的题（B7 金额不一致应取消、B8b 放任超时、B4 全故障、视觉门控对）对它公平；
   需要输密码的题（各 P-NORMAL、B6/B9/B10）对纯视觉 agent 存在平台性天花板。

> 说明：本节只记录测量结论。按用户要求，benchmark 的职责是**测出并判定**问题，
> 不代替被测对象（App / agent 框架）去修问题。
